# To brief

Use after something is settled and should be recorded. This skill doesn't interview: anything still undecided goes under Open decisions, not into the Brief. Other skills in this pack call this one whenever they write to the hub doc.

## Steps

1. Read the latest hub doc in full.
2. From the conversation, list:
   - **Decisions**: standing choices (a palette, a platform, a price range).
   - **Facts**: things now true (account created, domain connected), each dated.
   - **New questions**: things raised but not settled.
3. Update the doc:
   - **Brief**: change the affected rows. A reversal replaces the old wording; never add a contradicting row.
   - **Done so far**: one row per fact, with links not content. Correct rows the conversation proved wrong.
   - **Open decisions**: tick or remove what was settled; add new questions, precisely worded.
4. **Sweep for stale text.** Search the whole doc, starter prompts included, for anything the change made wrong (old name, colour, platform, price) and fix it.
5. Tell the user in 3–5 lines what changed.

## Rules

- Record only what the user said or confirmed.
- Merge with edits others made since your read; never overwrite them.
- If you can't reach the doc, give the updates as paste-ready text and say so.
