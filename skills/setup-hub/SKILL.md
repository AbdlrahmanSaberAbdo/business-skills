# Set up the hub

Run once per project. It creates the two things every later chat reads and writes: the **hub doc** and the **task sheet**. The other skills in this pack assume the structure below.

## Too small for a hub?

If the project is one offer, one channel, or a weekend test, don't build a hub. Say so, keep a short to-do list in the chat, and stop. Suggest running this skill again if it grows past what one chat can hold.

## Business type

Ask this first; it decides the extra Brief rows and the workstreams. Mixed businesses combine types.

- **What is sold:** physical product · digital product (SaaS, app, course, templates, content) · service.
- **Where it's delivered:** online · in person · both.

## The hub doc

Any editable doc the agent can read and write. Five sections, in this order:

1. **How to use this doc**: one paragraph. Run each workstream in a fresh chat with this doc's link; update Done so far and Open decisions before the chat ends.
2. **Brief**: table (Area | Decision) of standing choices. Write [TBD] for anything undecided. Never invent a decision.
   - **Every business:** type, offer, customer, problem it solves, main promise, price and pricing model, market, how customers find you, name, feel and voice, budget, what "launched" means.
   - **Physical product, add:** sourcing, stock, sales channel or store platform, payment, delivery, returns.
   - **Digital product, add:** platform or stack, MVP scope, billing (one-off, subscription, freemium), onboarding, support, data and privacy.
   - **Service, add:** who delivers it and capacity, packages, booking, contracts or terms, payment.
   - **In person, add:** location or area served, hours, permits and licences.
3. **Done so far**: table (Item | Status) of facts true now, each dated, with links instead of content.
4. **Open decisions**: checklist of precisely worded questions.
5. **Workstreams**: one heading each, with a starter prompt in a code block naming the doc link and the expected outcome.

## The task sheet

Any spreadsheet the agent can edit. Columns: **Task | Subtask | Status | Workstream | Blocked by | Notes**.

- Status: To do, Doing, Blocked, Done.
- A task with subtasks repeats its name on every subtask row, so the sheet filters cleanly.
- Blocked by lists the tasks that must be Done first.

## Steps

1. Ask what already exists (doc, sheet, site, accounts, logo, customers). Extend it rather than duplicating it. If the user mentions a doc or sheet without a link, ask for the link.
2. Ask the **business type**, then interview one question at a time, about 8 more at most, until every Brief row for that type is filled or [TBD]. Apply the **too small** check as the answers come in.
3. Create the hub doc.
4. Pick workstreams that fit, and write a starter prompt for each. Typical sets:
   - **Physical product:** identity, social, store, sourcing, pricing and margins, delivery and policies, launch content.
   - **Digital product:** identity, MVP, pricing and billing, landing page and waitlist, onboarding and support, terms and privacy, launch.
   - **Service:** identity, offer and packages, booking and operations, pricing, contracts, referrals and marketing.
   - **In person, add:** location, permits, local marketing.
5. Fill the task sheet as in **to-tasks**.
6. Name the first workstream and give the exact line to paste into a fresh chat.

## Rules

- Plain words, readable on a phone.
- Ask before creating accounts, paying, or publishing.
